Understanding app_numbers.py

The application fetches campsite availability data, parses the HTML grid returned by the park reservation site, and renders the results as a monochrome image. This document walks through the major steps and shows the code that powers each one.

1. Building the Daily Grid URL

The scraper starts by constructing the URL for the reservation grid that corresponds to the desired date. The build_url function fills in the query string parameters that the remote site expects. 

def build_url(for_dt: datetime) -> str:
    """Construct the daily reservation grid URL using the provided date."""
    params = dict(BASE_QUERY)
    params["StartDate"] = _mmddyyyy(for_dt)
    req = requests.Request("GET", f"{BASE_URL}{GRID_PATH}", params=params)
    return req.prepare().url

A fresh copy of the base query parameters is created for each request, the target date is inserted in the format the site uses (MM/DD/YYYY), and the prepared request returns the fully encoded URL.

2. Downloading the Reservation Grid

Once the URL is ready, the application downloads the HTML page and caches the result. The fetch_html helper also records the timestamp and the raw payload for reuse if the network request fails later. 

def fetch_html(for_dt: datetime) -> Optional[str]:
    global _last_payload, _last_fetched_utc, _last_error
    url = build_url(for_dt)
    try:
        r = requests.get(url, timeout=DATA_TIMEOUT, headers={"User-Agent": "trmnl-avail/1.0"})
        r.raise_for_status()
        _last_payload = r.text
        _last_fetched_utc = datetime.now(timezone.utc)
        _last_error = None
        return _last_payload
    except Exception as e:
        _last_error = str(e)
        log.error("Fetch failed: %s", e)
        return _last_payload

Successful responses overwrite the cached payload; otherwise, the prior HTML is returned so downstream code can keep running with the most recent data.

4. Rendering the Availability Image

The render_cached function orchestrates the full pipeline: it optionally returns a cached PNG, otherwise fetches the latest data, renders the layout, and caches the result for subsequent callers.

def render_cached(force: bool = False, output: str = "bytes"):
    global _last_img, _last_hash, _last_render_ts, _last_pil
    now_ts = time.time()
    cached = (
        _last_img is not None
        and (now_ts - _last_render_ts) < CACHE_SECONDS
        and (_last_pil is not None or output == "bytes")
    )

    if not force and cached:
        if output == "pil" and _last_pil is not None:
            return _last_pil.copy()
        return _last_img

    html = fetch_html(datetime.now(LOCAL_TZ))
    advisories = fetch_weather_advisories()

    ...
    if output == "pil":
        return _last_pil.copy()
    return _last_img

The cache avoids repeated network calls and image rendering work. When a fresh render occurs, the function stores both the PNG bytes and the Pillow image object so other parts of the program can reuse whichever representation they need.

5. Serving or Displaying the Result

Depending on the run mode, the application can serve the PNG over HTTP, render directly to an attached Inky display, or save a one-off file. The __main__ guard selects the appropriate path based on the RUN_MODE environment variable.

if __name__ == "__main__":
    if RUN_MODE == "once":
        content = render_cached(force=True)
        with open(OUTPUT, "wb") as f:
            f.write(content)
        print(f"Saved {OUTPUT}")
    elif RUN_MODE == "inky_once":
        run_inky_display(loop=False)
    elif RUN_MODE == "inky":
        run_inky_display(loop=True)
    else:
        start_server()

This makes it easy to repurpose the same core logic for offline rendering, a live display, or a lightweight web service that returns the latest image on demand.
